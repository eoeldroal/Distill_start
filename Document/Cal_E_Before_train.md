# traj 종류
traj 두 벌을 만듭니다. API 완결 풀이와 Base 완결 풀이입니다. 이 두 벌을 Base와 Post 두 모델로 각각 채점하니 네 칸이 나옵니다. 그리고 별도로 Post가 직접 생성하게 해서 Post가 어디에 서는지를 봅니다.

채점 대상	두 모델의 차이가 뜻하는 것	무게
Base 자신의 traj	post-training이 Base가 하던 것을 얼마나 버렸나	주 측정
API 완결 풀이	post-training이 강한 모델의 풀이를 얼마나 덜 그럴듯하게 보나	진단
두 번째에 대해서는 솔직히 기대치를 낮춰야 합니다. 짧은 버전(1,913개, 256토큰)으로 이미 해 봤고 결과가 무효였습니다 — 하락의 99.9%가 형식 관문과 전역 sharpening으로 설명되고, 문체를 고정하고 온도 효과까지 통제하면 방법 선택성이 우연 수준이었습니다(43개 층 중 3개, z=0.46). 완결 풀이로 바꾸면 단계 불일치 교란은 사라지지만, 방법 신호가 없던 것이 길이만으로 생기지는 않을 것 같습니다.

그러니 API traj의 본래 쓸모는 채점 대상이 아니라 분류 체계와 가치 인증입니다. 강한 모델 여섯이 방법 X로 실제로 정답에 도달했다면, X는 "잘못된 경로"가 아니라는 증거가 됩니다. 그게 리뷰어 반론에 대한 답이고, 채점으로 얻는 게 아니라 정답 여부로 얻는 것입니다.

## Base 의 경우 
### 분기는 엔트로피의 일정 수치 이상 터짐을 여부로 한다. 
엔트로피가 정확히 이 둘을 구별해 줍니다. 확신이 높은 위치(엔트로피 낮음)에서 갈라진 것은 잡음이고, 확신이 낮은 위치(엔트로피 높음)에서 갈라진 것은 진짜 갈림길입니다. 그리고 사용자가 말한 방식 — trunk를 하나 생성하고 갈림길을 찾아 거기서 강제로 갈라내는 것 — 은 트리를 운에 맡기지 않고 구성적으로 만듭니다. 같은 접두사를 강제로 공유시키므로 폭발이 없습니다.

독립 표집과 강제 분기의 차이가 이것입니다. 독립 표집은 24개가 각자 출발해 우연히 접두사를 공유하기를 바라는 것이고, 강제 분기는 접두사를 우리가 고정하고 그 뒤만 갈라내는 것입니다. 후자에서는 각 갈래에 원하는 만큼 표본을 붙일 수 있습니다.

그러면 branch가 잘 정의됩니다. 갈림길 노드에서의 token 선택 하나가 branch이고,

E_j = P_θ(token_j | 접두사) — softmax에서 정확히 읽힙니다. Monte Carlo 오차가 없습니다
B = exp(−Σ Ẽ_j log Ẽ_j) — 그대로 계산됩니다
checkpoint마다 드는 비용은 forward pass 한 번입니다
제가 포기하자고 했던 지표들이 다 살아납니다.

### Base의 traj의 유효성 판단을 위해서...
유효성 판정은 연구 대상이 아닌 실행자가 해야 합니다. 우리가 알고 싶은 것은 "이 경로가 답에 이를 수 있는가"이고 그건 경로의 성질이므로, 가장 강한 실행자로 재는 것이 맞습니다. 로컬에 있는 teacher(Qwen3-14B)가 적임이고 비용이 0입니다.

두 양을 따로 재고 어느 것도 삭제 근거로 쓰지 않습니다.

진입 확률 E_j: 갈림길에서 그 갈래를 고를 확률 (forward pass)
완성 능력 V_j: 그 갈래로 강제 진입시킨 뒤 정답에 이르는 비율 (강제 접두사 + verifier)
네 경우가 나오고, 주장은 하나에서만 합니다.

E_j	V_j	판독
떨어짐	유지	접근을 잃었고 능력은 남았다. 논문의 주장이 여기서만 성립합니다
떨어짐	떨어짐	애매합니다. 경로가 나빴는지 능력도 잃었는지 구별 안 됩니다
유지	떨어짐	접근이 아니라 실행이 나빠진 것입니다
유지	유지	아무 일도 없었습니다

# 지도 그리기 
쓸 수 있습니다. 그리고 이 설계에서 라벨의 역할이 두 가지로 명확해집니다.

첫째, 병합 지도. 갈림길에 후보 token이 k개 있는데, 그중 몇 개는 결국 같은 방법으로 이어집니다("Let"과 "First"가 둘 다 코시로 가는 경우). 각 후보에서 이어쓰기를 몇 개 뽑아 라벨을 붙이면 어느 후보들이 같은 방법인지 알 수 있고, 그것들을 하나의 branch로 묶습니다. 그러면 표현 취향의 변화(Let→We)가 branch 질량을 바꾸지 못하고 방법 간 이동만 측정됩니다.

둘째, 그림의 축 이름. branch가 cauchy, trig-param처럼 이름을 가지면 커버리지 플롯이 읽을 수 있는 그림이 됩니다. 이름 없는 "branch 3"보다 훨씬 낫습니다.

두 용도 다 panel 구축 때 한 번입니다. 규모를 계산해 보면,


100문제 × 갈림길 3개 × 후보 3개 × 이어쓰기 8개 = 7,200 라벨  (전 프로젝트 총량, 1회)

## 임베딩 지도
임베딩 지도도 다시 시험합니다. 완결 풀이가 되면 조건이 바뀌기 때문입니다. 절단 실험에서 텍스트를 짧게 자를수록 소스/방법 비가 나빠졌으니(전체 3.27 → 앞 30단어 8.42), 길어지면 개선될 가능성이 있습니다. 재판정은 이미 만들어 둔 4셀 검사와 diag_style_axis.py --tag로 한 명령입니다. 되살아나면 자유 배치 산점도를 쓸 수 있고, 안 되면 라벨 축으로 확정됩니다.
